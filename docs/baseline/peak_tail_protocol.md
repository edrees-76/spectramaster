# Low-energy tail in the peak model: evaluation protocol (pre-registered)

Written 2026-10-20, **before** the implementation and before any evaluation result. The limits
below must not be changed after results are known. A result outside a limit is reported as a
failure.

## Motivation

The engine fits pure Gaussians. Real HPGe and NaI peaks have a low-energy tail, from incomplete
charge collection and scattering. The baseline (`docs/baseline/before_T1`) shows the effect on the
synthetic `tailed` category, which has a 4 % tail with slope 1.5 sigma:

| | HPGe | NaI |
|---|---|---|
| area bias | -1.05 % | -1.42 % |
| z within ±1 sigma | 0.18 | 0.00 |
| z within ±2 sigma | 0.78 | 0.03 |

The areas are biased low and the stated uncertainties do not cover the error.

There is a second reason. Without a tail term, a residual search (Genie-style, see
`residual-search` work) takes the tail for a satellite peak.

The published Genie 2000 peak model includes a low-energy tail. This change follows that idea; no
vendor software was decompiled.

## Change

- The peak shape becomes a Gaussian plus a fraction eta of an exponentially modified Gaussian tail
  (slope tau, in sigma units) on the low-energy side. Both parts are area-normalised, so the area
  formula is unchanged.
- eta and tau are estimated per spectrum from strong isolated peaks (as the width model is) and are
  then held fixed for every peak.
- With too few strong peaks, or an eta that is not significant, eta = 0 and the fit is the current
  Gaussian fit unchanged.

## Data

- **Development:** whatever is needed while implementing. These are synthetic spectra with
  generator seeds outside the benchmark (`seed >= 940000`), and unit tests.
- **Test:** the benchmark categories as they are, generated by `seed_of`.
- **Reference sets:** IAEA G-1 and EML.
  - The G-1 peak *positions* near tails were looked at during the residual-search work (G1100 false
    components). G-1 area results were not used for any design decision.
  - G-1 is still reported, with that caveat.

## Criteria

New criteria for the `tailed` category, for each detector (HPGe and NaI):

| id | metric | limit | rationale |
|---|---|---|---|
| {det}.tailed.area_bias | mean relative area error | abs <= 0.005 | strong peaks: statistical sd is about 0.3 %; the tail must no longer bias the area |
| {det}.tailed.cov2 | fraction of \|z\| <= 2 | in [0.90, 0.98] | the stated uncertainties must cover the error |
| {det}.tailed.split | split fraction | <= 0.05 | the tail must not become a second peak |
| {det}.tailed.false_per_spectrum | unmatched peaks per spectrum | <= 1.5 | the baseline is about 1 for strong-peak spectra |
| {det}.tailed.cov1 | fraction of \|z\| <= 1 | report | |

All existing pre-registered criteria apply unchanged. The change is accepted only if none of them
goes from PASS to FAIL. This matters especially for `isolated_strong`, which has no tail in the
truth, so the estimator must not invent one, and for the weak-peak, doublet, efficiency, background,
identification and reference-set criteria. Runtime is reported.

Before and after: `docs/baseline/before_T1` (main at 2f54cc8, the same run as the residual-search
`before_R1`) and `docs/baseline/after_T1`.

## Result (2026-10-20): not accepted

| criterion | value | |
|---|---|---|
| HPGe.tailed.area_bias | +0.0015 (before -0.0105) | PASS |
| HPGe.tailed.cov2 | 0.94 (before 0.78) | PASS |
| HPGe.tailed.split / false_per_spectrum | 0.0 / 1.0 | PASS |
| NaI.tailed.area_bias | -0.0062 (before -0.0142) | FAIL |
| NaI.tailed.cov2 | 0.65 (before 0.03) | FAIL |
| G1.G1300.ratio_bias | 0.025 (before 0.0004) | PASS -> FAIL |

`isolated_strong` is unchanged: no tail is invented. The full test suite has one failure,
`test_measured_background_on_real_pairs`: the peak and spectrum background modes differ by more
than 2 %.

Cause: the tail is estimated per spectrum.

- The same detector got different tails in the G-1 spectra: eta 0.056-0.096 with tau 1.5-3.0, and
  none in G1200. Area ratios between spectra are therefore biased.
- The raw spectrum and the background-subtracted spectrum also get different tails.

The tail is a detector property. It belongs to a shape calibration, stored with the energy / FWHM
calibration as Genie does, and not to a per-spectrum estimate. The per-spectrum estimate is not
merged.

## Amendment (2026-10-20): detector shape calibration instead of a per-spectrum estimate

The tail is a detector property, so it is now part of a **peak-shape calibration**:

- `analysis.peaks.shape_calibration(spectra)` pools the strong isolated peaks of one or more
  calibration spectra.
- `set_peak_tail(spectrum, cal)` stores it in `extra["peak_tail"]`, which survives background
  subtraction and re-binning.
- `find_peaks`, the manual refit and the measured-background estimator read it from there.
- A spectrum without it is fitted exactly as before: Gaussian peaks, identical results.

The tailed-peak criteria above keep their **limits unchanged**. They now apply to the benchmark
category `tailed_shape_cal`: the `tailed` sample spectra, fitted with the shape calibration measured
on 3 separate calibration spectra of the same synthetic detector (seeds `seed_of(det, "shape_cal", i)`).
The uncalibrated `tailed` category stays as it was, as the baseline.

One criterion is added, `{det}.shape_cal.gaussian_area_bias` (abs <= 0.01, category
`strong_shape_cal`). It requires that a calibration measured on a tail-free detector does not bias
Gaussian peaks.

The per-spectrum results above have been seen. The G-1 check below is therefore informational.

Check before the benchmark: calibrating from G1100 alone and applying that shape to every G-1
spectrum gives G1300 ratio bias 0.0048 (per-spectrum estimate 0.025, no tail 0.0004; limit 0.02).
Recall, false peaks and G1300 coverage are unchanged.

## Result of the shape-calibration design (2026-10-20)

`docs/baseline/after_T1` against `before_T1`. **No pre-registered criterion went from PASS to
FAIL.** The full test suite gives 987 passed, 67 skipped and no failure;
`test_measured_background_on_real_pairs` passes.

| criterion | value | |
|---|---|---|
| HPGe.tailed.area_bias | +0.0014 (uncalibrated -0.0105) | PASS |
| HPGe.tailed.cov2 | 0.95 (uncalibrated 0.78) | PASS |
| HPGe.tailed.split / false_per_spectrum | 0.0 / 1.0 | PASS |
| HPGe.shape_cal.gaussian_area_bias | -0.00003 (calibration eta = 0) | PASS |
| NaI.tailed.area_bias | -0.0071 (uncalibrated -0.0142) | **FAIL** |
| NaI.tailed.cov2 | 0.57 (uncalibrated 0.03) | **FAIL** |
| NaI.tailed.split / false_per_spectrum | 0.0 / 0.1 | PASS |
| NaI.shape_cal.gaussian_area_bias | -0.0007 (calibration eta = 0) | PASS |

The calibrations measured on the synthetic detectors were:

- HPGe: eta 0.028, tau 2.0, from 18 peaks.
- NaI: eta 0.021, tau 1.5, from 15 peaks.
- The truth was eta 0.04, tau 1.5.
- Tail-free detectors gave eta = 0 for both detector types.

The NaI tail is underestimated, probably because the tail, the log-linear continuum and the step
are not well separated at 7 % resolution. This is a known limitation: the NaI criteria stay
failing until a better estimator is found, and their limits are not changed.

Default behaviour is unchanged. Spectra without a shape calibration, which today is all of them
because nothing sets one yet outside the API, are fitted exactly as before. Storing the
calibration per detector and the interface are the next increments.
